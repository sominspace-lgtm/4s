# Mobile First

Mobile is primary. Desktop is an expansion.

## Principles

- Design for one thumb.
- Use large touch targets.
- Avoid cramped inline controls.
- Prefer bottom sheets for focused decisions.
- Use fullscreen search.
- Make Quick Capture available everywhere.
- Keep forms short.
- Use progressive disclosure.

## Navigation

Mobile navigation should feel natural and stable.

Brief should always be easy to return to.

Recommended patterns:

- bottom navigation for core areas
- floating Quick Capture
- swipe down for Search
- long press for quick actions
- swipe right to complete
- swipe left to snooze or defer

## Forms

Forms should be calm and focused.

Show only fields needed for the current mode.

Password fields should not appear until password sign-in is selected.

Remember me should only appear in password login if functional.

## Reviews

Council and Weekly Review should become card-by-card experiences on mobile, not dense grids.

## Brief

Mobile Brief should be extremely short.

Recommended stack:

1. Greeting / status
2. One focus
3. Things needing attention
4. Optional rhythm/win
5. Quick Capture

## Offline and PWA

PWA behavior should feel trustworthy:

- clear offline states
- no silent data loss
- draft capture locally if possible
- sync later when possible

## Future mobile ecosystem

Long-term mobile should include:

- widgets
- lock screen glance
- watch complications
- voice capture
- location-aware reminders when user opts in
- share sheet capture
- calendar and mail integrations
