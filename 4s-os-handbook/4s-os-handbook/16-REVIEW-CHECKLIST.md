# Review Checklist

Use this after every meaningful design or code change.

## Product fit

- Does this support the Constitution?
- Does it help someone know what deserves attention?
- Does it make life easier?
- Does it reduce time spent managing the app?
- Does it feel like 4S OS rather than generic SaaS?

## Calm

- Does the screen feel calmer than before?
- Is there only one primary action?
- Is anything visually competing unnecessarily?
- Could any copy be shorter?
- Could any control be hidden until needed?

## Mobile

- Does it work beautifully on phone?
- Are touch targets large enough?
- Is typing minimized?
- Does it avoid cramped desktop patterns?
- Is the primary action obvious?

## Accessibility

- Is contrast acceptable across themes?
- Are fields labeled?
- Are buttons accessible?
- Does keyboard navigation work?
- Is reduced motion respected?

## AI

- Does AI reduce cognitive load?
- Is it too verbose?
- Is it too proactive for the selected Guide?
- Does it preserve user agency?
- Can the user dismiss or ignore it easily?

## Privacy

- Is the default private?
- Is sharing intentional?
- Is data export/deletion respected where relevant?
- Is trust explained before sensitive actions?

## Engineering

- Are errors handled?
- Are loading states handled?
- Are empty states handled?
- Could this cause stale data?
- Does it preserve RLS assumptions?
- Does it preserve existing routes and flows?

## Self-critique

Answer before finishing:

- What would Apple remove?
- What would Things 3 simplify?
- What would Linear make clearer?
- What would Muji make quieter?
- What would a tired user struggle with?
