# Accessibility

Accessibility is part of calm.

If a user has to strain, guess, zoom, or fight the interface, 4S OS has failed.

## Contrast

Maintain WCAG contrast for text and controls across all themes.

Do not hardcode colors without checking theme contrast.

## Touch targets

Mobile touch targets should be at least 44px by 44px.

Important actions should be easier to hit than secondary actions.

## Keyboard

Desktop should support keyboard navigation.

Recommended shortcuts:

- Cmd/Ctrl + K — Search
- Space — Quick Capture, if not typing
- Escape — close overlay
- Double Escape — return to Brief

## Screen readers

Use semantic HTML.

Label form fields clearly.

Use aria attributes when needed, but prefer native semantics.

Icon-only buttons need labels.

## Motion

Respect reduced motion.

Animations should never be required to understand state.

## Forms

Errors should be connected to fields.

Focus should move predictably.

Success and failure states should be announced or visible.

## Cognitive accessibility

Use plain language.

Avoid unexplained jargon.

Avoid too many choices.

Use progressive disclosure.

## Color independence

Never rely on color alone to communicate status.

Use labels, icons, or text.
